# Life Quest — 비즈니스 규칙서

MVP 범위([PRD](./PRD.md) §4)의 퀘스트 배정·만료·완료·EXP·레벨·업적·도감·칭호·친구·랭킹·보상 규칙. 프론트는 이 문서를 기준으로 화면 상태(로딩/성공/실패 문구)를 결정하고, 백엔드는 이 규칙대로 구현한다.

`[예시]` 표시된 수치는 밸런싱 조정 가능한 기본값이다. `[TBD]`는 팀 논의가 필요한 미확정 항목(제안 기본값 포함)이다.

## 1. 퀘스트 배정 규칙 (담당: 팀원1)

- 매일 자정 배치(또는 사용자의 당일 최초 로그인 시점)에 사용자별 오늘의 퀘스트를 배정한다. 개수 `[예시: 3개]`.
- **하드 제약** (만족 못 하면 후보에서 제외):
  - 레벨 게이팅 — `퀘스트.최소레벨 ≤ 사용자.레벨`
  - 최근 배정 제외 — 최근 `[예시: 7일]` 내 배정된 퀘스트는 제외
  - 위치 퀘스트는 사용자 GPS 반경 `[예시: 10km]` 이내 후보만 포함
- **다양성 규칙** — 배정 N개 안에서 동일 카테고리는 최대 `[예시: 2개]`까지.
- 하드 제약을 만족하는 후보가 N개 미만이면 "최근 배정 제외" 조건부터 순차 완화해 채운다.

## 2. 퀘스트 만료 규칙 (담당: 팀원1)

- 배정된 퀘스트는 **배정일 자정까지** 유효하다.
- 자정 배치가 그 시점까지 미완료(`ASSIGNED`) 상태인 퀘스트를 `EXPIRED`로 전이한다.
- 만료된 퀘스트는 EXP·보상을 지급하지 않으며, 완료 요청은 거부한다(§4).
- `[TBD]` 만료된 퀘스트가 바로 다음날 재배정 후보에 들어갈지: 기본값 = **들어간다**(만료는 "배정 이력"이 아니라 "미수행"으로 취급).

## 3. 위치 인증 규칙 (담당: 팀원2)

- 위치 기반 퀘스트는 목표 좌표 + 인증 반경을 가진다 `[예시: 100m]`.
- 클라이언트는 위도·경도·정확도(accuracy)·타임스탬프를 서버로 전송한다.
- 서버는 Haversine 공식으로 사용자-목표 간 거리를 계산해 인증 반경 이내인지 판정한다.
- **거부 조건**: ① 정확도 값이 임계 `[예시: 50m]` 초과 ② 타임스탬프가 `[예시: 5분]` 이상 경과(캐시된 위치 재사용 방지).
- 인증 성공 시 해당 UserQuest에 인증 시각을 기록하고, 그 퀘스트는 완료 가능 상태로 전이한다. 인증 없이는 완료 API가 거부된다.

## 4. 퀘스트 완료 규칙 · 멱등성 원칙 (담당: 팀원1 · 팀원3)

- 완료 조건: 일반 퀘스트는 사용자 액션(완료 버튼)만으로 충분. 위치 퀘스트는 §3 인증이 선행되어야 한다.
- **완료는 멱등해야 한다.** 이미 `COMPLETED`인 퀘스트에 완료 요청이 다시 오면 EXP·레벨·업적·도감을 **다시 갱신하지 않고** 최초 결과와 동일한 응답을 그대로 반환한다(중복 클릭·재시도로 인한 이중 지급 방지).
- 완료 처리는 하나의 트랜잭션 경계에서 함께 일어난다: 퀘스트 상태 전이 → EXP 지급 → 레벨 재계산 → 업적 진행도 갱신 → 도감 등록 → (해당 시) 보물상자 판정. 일부만 반영되는 부분 실패는 없다.

## 5. EXP 지급 규칙 (담당: 팀원3)

| 퀘스트 등급 | 기본 EXP `[예시]` |
|---|---|
| 일반 | 10 |
| 희귀 | 25 |
| 영웅 | 50 |
| 전설 | 100 |

콤보·연속 출석 보너스는 **Phase 2**(MVP에 없음). EXP는 §4 트랜잭션 안에서만 지급된다.

## 6. 레벨 규칙 (담당: 팀원3)

레벨업에 필요한 누적 EXP `[예시 — 밸런싱 조정 가능]`:

| 레벨 | 필요 누적 EXP |
|---|---|
| 1 → 2 | 100 |
| 2 → 3 | 250 |
| 3 → 4 | 450 |
| 4 → 5 | 700 |
| 5 → 10 | 레벨당 +400 씩 증가 |

레벨업 보상:

| 레벨 | 보상 |
|---|---|
| Lv 2 | 프로필 테두리 |
| Lv 5 | 칭호 |
| Lv 10 | 희귀 퀘스트 해금 |
| Lv 15 | 아바타 꾸미기 |
| Lv 20 | 지역 퀘스트 |
| Lv 30 | 전설 업적 |

- EXP 지급 직후 같은 트랜잭션에서 레벨업 여부를 판정한다. 한 번의 완료로 여러 레벨을 동시에 넘을 수 있다(연속 처리).
- 레벨업 보상 지급도 멱등이다 — 동일 레벨업 이벤트에 대해 중복 지급하지 않는다.

## 7. 업적 규칙 (담당: 팀원3)

- 업적은 조건(예: 카테고리 N회 완료)과 단계(I~V)로 구성된다. 단계 임계값 `[예시: 10 / 30 / 100 / 300 / 1000]`.
- 완료 이벤트마다 관련 업적의 진행 카운트가 증가하고, 임계 도달 시 해당 단계를 달성 처리하며 보상을 지급한다.
- 업적 달성은 **단조 증가**한다(되돌아가지 않음).

## 8. 도감(LifeDex) 규칙 (담당: 팀원3)

- 카테고리별 하위 항목(장소·음식 등)을 최초로 완료하면 도감에 등록된다.
- 수집률 = 등록된 항목 수 / 해당 카테고리 전체 정의 항목 수.
- 항목 소스는 공공데이터(TourAPI·문화포털)로 채워진 place 목록을 기준으로 한다.

## 9. 칭호 규칙 (담당: 팀원3 · 팀원4)

- 특정 레벨·업적 달성 시 칭호가 해금된다.
- 사용자는 해금된 칭호 중 하나를 "대표 칭호"로 장착할 수 있다(미장착 시 프로필에 표시 안 함).

## 10. 친구 · 랭킹 규칙 (담당: 팀원4)

- 친구는 요청 → 수락 절차로 성립한다(`PENDING` → `ACCEPTED`).
- 랭킹은 **주간 단위**(매주 월요일 리셋)로 이번 주 획득 EXP 합산 기준 정렬한다.
- `[TBD]` 실시간 정렬 구현 방식: 제안 = Redis Sorted Set(EXP 지급 시 갱신). 구현 부담이 크면 대안으로 `[예시: 5분 주기]` 배치 스냅샷으로 시작 가능.

## 11. 보상 규칙 — 레벨업 보상 · 보물상자 (담당: 팀원4)

- 레벨업 보상은 §6 표에 연동되어 레벨업 시 자동 지급된다(레벨업 이벤트당 1회, 멱등).
- 보물상자는 퀘스트 완료 시 확률 `[예시: 10%]`로 등장하며, 보상 종류(소량 EXP·코인·칭호·스킨 등)를 무작위로 지급한다. 지급 로직도 §4의 완료 트랜잭션 안에서 함께, 멱등하게 처리한다.
