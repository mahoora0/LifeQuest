# Life Quest — 화면 명세서

화면별 목적 · 상태 · **버튼 동작** · 빈 화면 · 오류 상태를 정의한다. 흐름은 [화면 흐름도](./screen-flow.md), 상태 값·에러 코드는 [API 명세서](./api-spec.md), 판정 규칙은 [비즈니스 규칙서](./business-rules.md) 참조.

## 공통 규칙

- **빈 화면**은 "오류"와 구분한다 — 데이터가 없는 정상 상태(예: 아직 친구 없음)는 안내 문구 + CTA, 통신 실패는 오류 문구 + **재시도 버튼**을 노출한다.
- 오류 문구는 화면마다 새로 정의하지 않고 [API 명세서](./api-spec.md) §0의 코드→문구 매핑 테이블을 공용으로 둔다. `UNAUTHORIZED`(토큰 만료)는 어느 화면에서든 로그인 화면으로 이동시킨다.
- 완료 결과·레벨업 보상 팝업은 **하나의 완료 API 응답**에서 파생된다([비즈니스 규칙서](./business-rules.md) §3 — 한 트랜잭션). 별도로 순차 호출하지 않는다.
- 요청 진행 중에는 해당 버튼을 비활성화하고 로딩 표시를 한다(중복 탭 방지 — 완료 API는 서버에서도 멱등 처리).

## 1. 로그인 (담당: 팀원1)

- **목적**: 인증, JWT 발급·저장
- **상태**: 기본 / 로딩 / 오류
- **버튼 동작**:
  - `로그인` — 입력 검증(이메일 형식·비밀번호 존재) 후 `POST /auth/login`. 성공 시 토큰 저장 후 홈으로 이동.
  - `회원가입` — 회원가입 화면으로 이동.
- **오류 상태**: `UNAUTHORIZED`(자격 불일치) → "이메일 또는 비밀번호가 올바르지 않습니다" 인라인 표시. `VALIDATION_ERROR` → 필드별 인라인 표시.

## 2. 회원가입 (담당: 팀원1)

- **목적**: 계정 생성
- **상태**: 기본 / 필드 검증 오류 / 로딩 / 완료
- **버튼 동작**:
  - `가입하기` — 클라이언트 검증(이메일 형식·비밀번호 정책·닉네임 길이) 후 `POST /auth/signup`. 성공 시 완료 안내 후 로그인 화면으로 이동.
  - `로그인으로 돌아가기` — 로그인 화면으로 이동.
- **오류 상태**: `CONFLICT`(이메일/닉네임 중복) → 해당 필드에 인라인 표시. `VALIDATION_ERROR` → 필드별 인라인 표시.

## 3. 홈 · 오늘의 퀘스트 (담당: 팀원1)

- **목적**: 오늘 배정된 퀘스트 목록 확인 — 서비스의 시작점
- **상태**: 로딩 / 목록 / 빈 화면 / 오류
- **버튼 동작**:
  - 퀘스트 카드 탭 — 퀘스트 상세로 이동.
  - 하단 탭(마이페이지 · 친구/랭킹) — 각 화면으로 이동.
  - 당겨서 새로고침 — `GET /quests/today` 재호출.
- **빈 화면**: ① 배정 전 → "오늘의 퀘스트를 준비 중이에요" ② 전부 완료 → "오늘의 퀘스트를 모두 완료했어요! 🎉" (두 상태를 구분해 표기)
- **오류 상태**: 통신 실패 → 재시도 버튼.
- 카드에는 제목·카테고리·등급(⚪🔵🟣🟠)·EXP·상태(`ASSIGNED`/`COMPLETED`)를 표시한다.

## 4. 퀘스트 상세 (담당: 팀원1)

- **목적**: 퀘스트 정보 확인 · 완료 진입점
- **상태**: 기본(미완료) / 완료 처리 중 / 완료됨(읽기 전용) / 만료됨
- **버튼 동작**:
  - `퀘스트 완료` — 확인 다이얼로그("현실에서 수행하셨나요?") 후 `POST /quests/{userQuestId}/complete`(idempotencyKey 포함). 성공 시 완료 결과 팝업 표시. 처리 중 버튼 비활성화.
  - `뒤로` — 홈으로 복귀.
- **오류 상태**: `CONFLICT`(만료) → "기한이 지난 퀘스트예요" 표시 후 버튼 숨김. `NOT_FOUND`/`FORBIDDEN` → 홈으로 복귀 + 토스트.
- 완료됨 상태에서는 완료 버튼 대신 획득 EXP·완료 시각을 표시한다.

## 5. 완료 결과 팝업 (담당: 팀원2 · 팀원3)

- **목적**: EXP 획득·도감 등록·업적 진행 피드백
- **상태**: 기본 결과 / 레벨업 연출 포함
- **데이터 소스**: `POST /quests/{userQuestId}/complete` 응답(추가 호출 없음)
- **버튼 동작**:
  - `확인` — `levelUp: true`면 레벨업 보상 팝업으로 전환, 아니면 팝업 닫고 홈 복귀(완료 상태 반영된 목록 갱신).
- 표시 요소: 획득 EXP, EXP 게이지(현재/다음 레벨), `lifedexUnlocked`(새 도감 등록), `achievementsProgressed` 중 `tierUp: true` 항목.

## 6. 레벨업 보상 팝업 (담당: 팀원3 · 팀원4)

- **목적**: 레벨업 축하 · 보상 안내
- **노출 조건**: 완료 응답의 `levelUp: true`일 때만(조건부)
- **버튼 동작**:
  - `보상 확인` — `levelRewards` 목록 표시(예: 프로필 테두리, 칭호). 꾸미기 아이템이면 "마이페이지에서 장착할 수 있어요" 안내.
  - `닫기` — 홈으로 복귀.
- 한 번의 완료로 여러 레벨을 넘은 경우([비즈니스 규칙서](./business-rules.md) §5) 최종 레벨 기준으로 합산 표시한다.

## 7. 도감 · LifeDex (담당: 팀원3)

- **목적**: 카테고리별 경험 수집 현황
- **상태**: 로딩 / 카테고리 목록 / 항목 목록 / 빈 화면(수집 0) / 오류
- **버튼 동작**:
  - 카테고리 카드 탭 — `GET /lifedex/{category}` 호출 후 항목 목록으로 전환.
  - 항목 탭 — 수집됨: 수집 일시 표시. 미수집: 실루엣(?) 처리, "관련 퀘스트를 완료하면 등록돼요" 안내.
  - `뒤로` — 카테고리 목록 ↔ 마이페이지 복귀.
- **빈 화면**: 전체 수집 0 → "첫 퀘스트를 완료하고 도감을 채워보세요" + `오늘의 퀘스트 보기` CTA.
- **오류 상태**: 통신 실패 → 재시도 버튼.
- 카테고리 카드에 수집률(`collected/total` + 게이지), 상단에 전체 진행률을 표시한다.

## 8. 업적 · 칭호 (담당: 팀원3)

- **목적**: 업적 진행 확인 · 칭호 장착
- **상태**: 로딩 / 목록 / 장착 처리 중 / 오류
- **버튼 동작**:
  - 탭 전환(`업적` / `칭호`) — 목록 전환(`GET /achievements`, `GET /titles`).
  - 칭호 `장착` — `POST /titles/{titleId}/equip`. 성공 시 기존 대표 칭호는 자동 해제 표시. 미보유 칭호는 버튼 비활성 + 해금 조건 표시.
  - 칭호 `해제` — `DELETE /titles/equip`.
- **오류 상태**: `FORBIDDEN`(미보유 칭호 장착 시도) → 토스트. 통신 실패 → 재시도 버튼.
- 업적 카드: 이름·현재 단계(I~V)·진행 게이지(`progress/nextThreshold`). 달성 단계는 배지로 강조.

## 9. 마이페이지 · 프로필 꾸미기 (담당: 팀원4)

- **목적**: 내 정보 확인 · 프로필 꾸미기(테두리·배경·배지) · 대표 칭호/업적 지정
- **상태**: 기본 / 편집 모드 / 저장 중 / 오류
- **버튼 동작**:
  - `편집` — 닉네임·대표 업적 수정 모드. `저장` 시 `PATCH /users/me`.
  - `꾸미기` — `GET /users/me/inventory`로 보유 아이템 그리드 표시. 아이템 탭 → `POST /inventory/{id}/equip`(같은 슬롯 기존 장착 자동 해제), 장착 중 아이템 재탭 → `unequip`.
  - `도감` / `업적·칭호` — 각 화면으로 이동.
  - `로그아웃` — 확인 다이얼로그 후 토큰 삭제, 로그인 화면으로 이동.
- **빈 화면**: 보유 아이템 없음 → "레벨업 보상으로 아이템을 모아보세요".
- **오류 상태**: `CONFLICT`(닉네임 중복) → 인라인 표시. 통신 실패 → 재시도 버튼.

## 10. 친구 목록 (담당: 팀원4)

- **목적**: 친구 관리(요청·수락·거절)
- **상태**: 로딩 / 목록 / 빈 화면 / 요청 처리 중 / 오류
- **버튼 동작**:
  - `친구 추가` — 닉네임(또는 이메일) 검색 후 `POST /friends/{userId}/request`. 성공 시 "요청 보냄" 상태로 표기.
  - 받은 요청 `수락` / `거절` — `POST /friends/{userId}/accept` / `.../reject`. 처리 중 해당 행 버튼 비활성화.
  - 친구 행 탭 — 친구 프로필(`GET /friends/{userId}/profile`)에서 레벨·EXP·대표 업적 비교.
- **빈 화면**: 친구 없음 → "함께 성장할 친구를 추가해보세요" + `친구 추가하기` CTA.
- **오류 상태**: `CONFLICT`(이미 친구/요청 중/자기 자신) → 토스트. `NOT_FOUND`(검색 결과 없음) → "사용자를 찾을 수 없어요"(오류 아닌 안내). 통신 실패 → 재시도 버튼.

## 11. 주간 랭킹 (담당: 팀원4)

- **목적**: 나 + 친구 간 주간 EXP 순위
- **상태**: 로딩 / 목록 / 빈 화면(친구 없음) / 오류
- **버튼 동작**:
  - 랭킹 행 탭 — 친구 프로필로 이동(본인 행은 마이페이지).
  - 당겨서 새로고침 — `GET /ranking/weekly` 재호출.
- **빈 화면**: 친구가 없으면 내 순위만 표시하고 "친구를 추가하면 함께 경쟁할 수 있어요" + `친구 추가` CTA.
- **오류 상태**: 통신 실패 → 재시도 버튼.
- 내 행은 강조 표시(`isMe`), 상단에 주 시작일(`weekStart`)과 리셋 안내("매주 월요일 초기화")를 표시한다.
