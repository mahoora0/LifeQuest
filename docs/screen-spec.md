# Life Quest — 화면 명세서 (라이트)

화면별 목적·주요 상태·연결 API만 정리한다. 버튼 단위 세부 인터랙션은 각 화면 담당자가 구현하며 확정한다 — 여기서는 **전원이 API·상태를 헷갈리지 않도록** 최소 계약만 고정한다. 흐름은 [화면 흐름도](./screen-flow.md), 상태 값·에러 코드는 [API 명세서](./api-spec.md) 참조.

| 화면 | 담당 | 목적 | 주요 상태 | 연결 API |
|---|---|---|---|---|
| 로그인 | 팀원1 | 인증 | 기본 / 로딩 / 오류(자격 불일치) | `POST /auth/login` |
| 회원가입 | 팀원1 | 계정 생성 | 기본 / 검증 오류(이메일 중복 등) / 로딩 | `POST /auth/signup` |
| 홈 · 오늘의 퀘스트 | 팀원1 | 오늘 배정된 퀘스트 목록 | 로딩 / 목록 / **빈 화면**(배정 전 or 전부 완료) / 오류 | `GET /quests/today` |
| 퀘스트 상세 | 팀원1 | 퀘스트 정보 확인 · 완료 진입점 | 기본(미완료) / 완료됨(읽기 전용) / 만료됨 | `GET /quests/{userQuestId}` |
| 지도 · GPS 인증 | 팀원2 | 위치 기반 퀘스트 인증 | 대기 / 인증 중 / 성공 / 실패(반경 밖·정확도 낮음) | `POST /quests/{userQuestId}/verify-location` |
| 완료 결과 팝업 | 팀원3 | EXP 획득 피드백 | 기본 결과 / 레벨업 연출 포함 | `POST /quests/{userQuestId}/complete` 응답 |
| 레벨업 보상 팝업 | 팀원3 · 팀원4 | 레벨업 보상 안내 | 레벨업 시에만 노출(조건부) | 완료 응답의 `levelUp` 필드 |
| 보물상자 팝업 | 팀원4 | 랜덤 보상 연출 | 등장 시에만 노출(조건부) | 완료 응답의 `chestReward` 필드 |
| 도감(LifeDex) | 팀원3 | 카테고리별 수집 현황 | 로딩 / 목록(수집률 표시) / **빈 화면**(0%) | `GET /lifedex` |
| 업적 · 칭호 | 팀원3 | 달성 현황 · 칭호 장착 | 로딩 / 목록 / 장착 처리 중 | `GET /achievements`, `POST /titles/{id}/equip` |
| 프로필 | 팀원4 | 내 정보 · 대표 칭호 표시 | 기본 / 편집 모드 | `GET /users/me`, `PATCH /users/me` |
| 친구 목록 | 팀원4 | 친구 관리 | 로딩 / 목록 / **빈 화면**(친구 없음) / 요청 대기중 | `GET /friends`, `POST /friends/{userId}/request` |
| 주간 랭킹 | 팀원4 | 친구 간 순위 | 로딩 / 목록 / **빈 화면**(친구 없음) | `GET /ranking/weekly` |

## 공통 규칙

- **빈 화면**은 "오류"와 구분한다 — 데이터가 없는 정상 상태(예: 아직 친구 없음)는 안내 문구 + CTA(예: "친구 추가하기"), 통신 실패는 재시도 버튼을 노출한다.
- 표준 오류 응답 형식과 코드는 [API 명세서](./api-spec.md) §1을 따른다 — 화면마다 오류 문구를 새로 정의하지 않고 코드→문구 매핑 테이블을 공용으로 둔다.
- 완료·레벨업·보물상자 팝업은 **하나의 완료 API 응답**에서 파생된다([비즈니스 규칙서](./business-rules.md) §4 — 한 트랜잭션) — 별도로 순차 호출하지 않는다.
